# Shared decision core

The core validates a prepared task, dispatches through the explicitly selected provider adapter, validates the returned operation record, and evaluates the local acceptance profile. It returns an outcome for the application's runner to store and interpret.

Python implementation: [`decision_kit/universal.py`](../../packages/decision-kit/decision_kit/universal.py) and [`decision_kit/core.py`](../../packages/decision-kit/decision_kit/core.py), documented in [`decision-kit`](../../packages/decision-kit/README.md), provide the universal API, provider registry, validation, and evaluation. [`decision_kit/cli.py`](../../packages/decision-kit/decision_kit/cli.py) implements bounded batch planning, atomic receipts, resume, and spend admission; [`decision_kit/providers/plusvibe.py`](../../packages/decision-kit/decision_kit/providers/plusvibe.py) is the shipped Python transport. TypeScript implementation: [`bounded-decision-core/src/index.ts`](../../packages/bounded-decision-core/src/index.ts), documented in its [README](../../packages/bounded-decision-core/README.md), provides provider-neutral task validation, adapter selection, record validation, and local evaluation. [`jev-decision-core/src/adapter.ts`](../../packages/jev-decision-core/src/adapter.ts) adds the current Jev protocol transport and record mapping.

Both runtimes implement the shared JSON contract. Their runner scope differs: Python decision-kit owns a multi-case CLI and receipt lifecycle; TypeScript modules perform a single operation and leave durable runner lifecycle to the host application.
